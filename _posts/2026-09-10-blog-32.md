## Key Points

- Tool outputs from systems like Jira, GitHub, Salesforce, and Postgres are often trusted because they come from internal systems, but can contain untrusted content from customers, contributors, or web forms
- Prompt injection attacks can occur when AI agents read poisoned content from untrusted fields within trusted systems, redirecting authorized capabilities to attacker goals
- Current security screens (input screening, output screening, action screening) examine isolated moments but miss the sequence of result-then-call that constitutes an attack
- Traditional detection methods like delimiters and sandwiching can be bypassed by adaptive attackers who optimize against these patterns
- The most effective defense involves baselining individual agent behavior, monitoring for deviations in tool calls or arguments, and enforcing policies based on historical patterns
- Coding agents in remote development environments are particularly vulnerable as they combine untrusted repository content with high-privilege tools like shell execution
- Coercion attacks work by making authorized agents perform unusual but technically valid operations they've never done before, like querying new database tables or emailing new addresses
- ARMO's Application Profile DNA (APD™) approach builds per-agent behavioral baselines from kernel-level execution observation
- The solution involves three steps: re-labeling tool inventory by field, ranking agents by risk, baselining top-risk agents, and moving from audit to enforcement
