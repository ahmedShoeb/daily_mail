## Key Points

- Modern agent memory systems come in three main shapes: file-based memory (curated markdown files), structured memory (embedded facts in vector stores), and experience memory (trained into model weights).
- File-based memory (used by Claude Code, Cursor, etc.) relies on LLM curation and text search, while structured memory (used by mem0, Letta, Zep) uses embeddings and ranked retrieval.
- Structured stores significantly outperform file-based memory on benchmarks: 73.6% vs 44.9% accuracy on LongMemEval, with structured memory also being more token-efficient.
- File-based memory excels at abstention (saying 'I don't know') because it remembers less and over-answers less, while eager retrieval needs explicit abstention discipline.
- Within structured memory, there are two lineages: place-organized (MemPalace) and entity-and-time (Zep's Graphiti) which differ in cost profiles and aggregation capabilities.
- The hybrid approach (place-organized core with temporal validity windows) beat pure vector indexes by 15 points on long-history benchmarks but tied on shorter ones.
- Graph-based memory with LLM extraction is expensive at scale: costing roughly $14 per long user history vs $0.03 for embedding-only approaches.
- Retrieved experience memory only helps when the AI actor has 'headroom' - it helps weaker models but shows no detectable benefit for frontier models on tested benchmarks.
- Training-based memory (like MemHarness) achieves higher performance but requires reinforcement learning and becomes inseparable from the model weights.
- No single benchmark comprehensively ranks memory systems, and evaluation stack differences can matter more than architectural choices in some cases.
