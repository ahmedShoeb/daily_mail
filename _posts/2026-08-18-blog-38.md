## Key Points

- The author's kernel patches for VRAM management improvements have been merged upstream and will be available in Linux 7.3
- Running out of VRAM doesn't have to be catastrophic - with proper management, games can handle VRAM overcommit surprisingly well
- Performance degradation when using CPU RAM instead of VRAM comes from PCIe bus limitations, with a hard theoretical limit of ~1GiB transfer per frame at 30 FPS
- The article describes a critical kernel deadlock issue that caused command submission failures when VRAM was exhausted, which required significant debugging and fixing
- The system experienced 'ping-pong' memory movement where memory kept getting evicted and moved back repeatedly between competing applications
- Display hardware requiring physically contiguous VRAM for scanout data creates major challenges during memory eviction, sometimes requiring up to 4GiB of VRAM to be cleared for just 32MiB of scanout data
- The author developed heuristics with 'hard throttle' and 'soft throttle' phases to manage memory reclamation more intelligently
- With these improvements, games can handle up to 1GiB of VRAM overcommit while maintaining playable performance (19.6ms per frame average)
- Applications can use APIs like VK_EXT_pageable_device_local_memory to provide memory priority hints, helping drivers make smarter eviction decisions
- The work is already available in SteamOS and the author is working on upstreaming the kernel changes for broader Linux distribution support
