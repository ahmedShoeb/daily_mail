## Key Points

- Codex's memory system can select conversations from local providers and send them to OpenAI without user consent or provider boundary restrictions
- The issue was discovered when a user received an OpenAI "cyber abuse" warning for conversations that only existed in private local provider chats
- The vulnerability occurs because memory candidate selection doesn't filter by provider, allowing local conversations to be processed by OpenAI-backed sessions
- This traffic happens even when analytics and OpenTelemetry are disabled, as it's model-inference traffic not governed by those controls
- The reporter characterizes this as "data exfiltration" where private data crosses provider boundaries without informed authorization
- Tests confirm the vulnerability in version 0.150.0-alpha.12.2, where unique test content was sent to OpenAI and processed
- The current redaction system only filters narrow secret patterns (like API keys) but doesn't protect personal data, privileged material, or filesystem identities
- Users can't prevent this without fully disabling the Memories feature - analytics/telemetry controls don't affect this channel
- The reporter demands OpenAI audit account actions, reverse penalties based on this data, notify affected users, and publish an official response
- Documentation doesn't clearly disclose that conversations from one provider can be sent to another, including OpenAI
