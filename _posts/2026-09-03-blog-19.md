## Key Points

- Agent exposure layers are critical for moving AI agents from demos to production, as most failures occur at the interface layer rather than in the models themselves.
- Four exposure patterns exist: direct API invocation for internal services, gateway-mediated for external APIs, event-driven for async workflows, and MCP server interfaces for multi-agent architectures.
- Agent APIs differ significantly from ordinary APIs with large context payloads, slow incremental responses, non-deterministic outputs, and free-text payloads that require special handling.
- The AWS Lambda integration tier should use thin per-consumer adapters over a shared agent core to handle different consumer needs like timeouts, memory, and concurrency.
- AWS WAF provides volumetric protection but can't inspect most of an agent's large payload - content controls must be implemented structurally and semantically.
- Agent logging requires a tiered approach due to volume and sensitivity concerns: metadata logs, hashed content logs, and sampled full-fidelity logs.
- Caching for agents is complex due to non-deterministic responses - prompt caching (safe) should be prioritized over response caching, with semantic caching requiring careful threshold setting.
- Multi-tenant exposure requires per-tenant isolation in the integration tier, token budgeting alongside request quotas, and knowledge base filtering.
- Progressive rollout for agents needs session stickiness and behavioral monitoring beyond just error rates to detect quality regressions.
- Partner tools from AWS Marketplace (like Tyk, Kong, KrakenD, and Portkey AI) solve specific problems but have adoption thresholds based on team scale and requirements.
