## Key Points

- diffium-db is a terminal UI tool that provides live monitoring of database changes while work is happening, not just post-hoc analysis
- The tool was created to address the problem of not knowing what database migrations actually do in real-time, especially when AI agents are making changes
- You point it at a Postgres database, take a baseline snapshot, and it re-reads the database every second to show changes in a split-pane interface
- It monitors tables, views, materialized views, enums, functions, and critically - also watches individual row changes
- The tool has four main commands: watch (opens the TUI), snapshot (takes baseline), baselines (lists snapshots), and diff (prints changes and exits)
- For safe testing, it's recommended to point diffium-db at a database branch (like Neon's branches) where agents can work on copies that can be thrown away if needed
- Row diffing uses fingerprinting (primary key + hash of the whole record) to track changes efficiently without storing every row
- When tables gain columns, diffium-db intelligently marks row update counts as approximate since every hash changes but users didn't edit the rows
- Structural diffs work by rendering objects to canonical text blocks with deterministic line order, then doing line diffs
- Future improvements planned include ORM awareness, support for other databases beyond Postgres, and potentially using logical replication instead of polling
